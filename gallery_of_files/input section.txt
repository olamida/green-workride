WorkRide UI Overhaul: Apple × Elon Musk Award-Winning Mobile-First Architecture & Implementation Guide
This is a complete, from-scratch rebrand of the WorkRide Rider PWA (and supporting Ops views) as if the current UI has never been touched. Mobile phone is the primary canvas (users are literally on the move — walking to junctions, waiting at Berger, riding). Desktop/web is a responsive secondary layer that never compromises the mobile experience.
Guiding philosophy (Apple HIG + Apple Design Awards + first-principles Elon style):

Clarity — Every screen answers three questions instantly: Where am I? What can I do? Where can I go next?
Deference — Content (map, corridor chips, live seats, impact) is the hero. Chrome recedes.
Depth — Layered cards, subtle glass, purposeful motion, and spatial hierarchy.
Inclusivity & Accessibility — Full VoiceOver/Dynamic Type/high-contrast/large targets, Pidgin-friendly language, low-literacy modes, offline-first.
Social Impact — Every screen surfaces community value (verified colleagues, subsidy, CO₂ saved, road intelligence, free volunteer rides).
Delight & Interaction — Large, thumb-zone primary actions, haptic feedback, live seat counters, “leaving soon” pulse, progressive disclosure.
Innovation — Corridor-first fixed-price model + demand hotspots + soft-hold + road sensors made beautiful and glanceable.

Uber lessons applied and improved: map-centric but never overwhelming, color-as-signal only, 3-taps-or-less core flows, bottom sheets, massive search/destination targets, real-time status always visible.
Target outcomes (Apple Design Award categories):

Interaction & Inclusivity winners through accessibility + thumb-first design.
Social Impact through transparent subsidy, impact certificates, road data for public good.
Delight through live corridor chips, soft-hold countdown, Green Points, CO₂ trees.
Visuals through refined Forest Green / Gold / Slate system + Liquid-Glass-inspired materials adapted for low-end Android + iOS.


1. Design System Foundation (Implement First — Non-Negotiable)
File: resources/css/design-system.css (single source of truth). All Tailwind @theme tokens live here. Never hard-code colors or spacing elsewhere.
Color Tokens (semantic, not decorative):

--wr-forest #1B5E20 (primary actions, success, verified)
--wr-gold #F9A825 (accent, free/volunteer, premium)
--wr-slate #0F172A (text, high-emphasis)
--wr-paper #F8FAF8 (backgrounds)
--wr-surface #FFFFFF + 12% white glass overlays
Semantic: --wr-success, --wr-warning (leaving soon), --wr-danger, --wr-info
Dark mode: invert with high-contrast ratios ≥ 4.5:1 (WCAG AA, prefer AAA for text).
Color is signal only: green = confirmed/boarded/verified, gold = free/volunteer/Green Points, red = full/cancelled/overdue.

Typography:

Headings: Sora (or system SF Pro / Inter as fallback)
Body: Inter
Numbers/mono: JetBrains Mono or system mono
Scale: 8px base grid. Large Dynamic Type support. Minimum body 16px, primary CTAs 17–18px bold.
Line length max ~60–70 characters on mobile.

Spacing & Layout:

8px grid everywhere.
Safe-area insets respected (notch, home indicator).
Thumb zone: primary actions in bottom 1/3 of screen.
Cards: 16–20px radius, soft shadow or glass blur(20px) + 12% white.

Components (build as Alpine + Blade reusable components):

CorridorChip (large pill, live pulse, seats, fare, IRI color)
LiveTripCard (avatar + verification badge + 5-sec road clip placeholder + seats + score reasons)
BottomSheet (standard for filters, confirm, soft-hold)
PrimaryButton (full-width or large, 56px min height, haptic on press)
StatusBadge (Leaving Soon, Soft Hold, Verified L3, Free)
WalletPill (dual balance cash + subsidy)
ImpactBadge (CO₂ / trees)
EmptyState with demand CTA (“12 people want this — Be the driver”)

Motion & Haptics:

200ms spring for sheets and cards.
Haptic: light on confirm, medium on seat reserved, success on boarded.
Prefer system haptics via Vibration API / iOS equivalents.
Reduce motion respect.

Accessibility baseline (apply to every screen):

Semantic HTML + ARIA labels.
VoiceOver / TalkBack tested labels.
Focus order logical.
High contrast mode.
Large touch targets ≥ 44×44 pt.
Offline indicators always visible.
Language: English primary + Pidgin-friendly microcopy option.


2. Information Architecture & Global Navigation (Mobile-First)
Bottom Tab Bar (fixed, 5 items max, thumb-friendly):

Go (home / board / map) — primary
My Rides
Wallet
Impact (CO₂, Green Points, certificates)
Profile (verification, settings, templates)

Floating action button (FAB) on Go screen only for “Publish / Be the driver” when Level 1+.
Top bar: minimal — logo left, search/destination or corridor chips center/right, profile avatar or notification bell.
Progressive disclosure rule: Never show more than 3 primary actions at once. Secondary actions go into bottom sheets or overflow.

3. Screen-by-Screen Implementation Guide (Step-by-Step for AI Code Writer)
Implement in this exact order. Each screen has: purpose, layout hierarchy, components, interactions, states, accessibility, data requirements.
Screen 1: Splash / Onboarding (First Launch + Returning)

Full-bleed subtle map or corridor abstract with Forest/Gold gradient.
Logo + tagline: “Get to work. Every day. Verified.”
3-screen carousel (swipe or auto): 1) Verified colleagues 2) Fixed fair prices + subsidy 3) Road intelligence + CO₂ impact.
Primary CTA: “Continue with Phone” (Tier-0 OTP) or “Continue with Google” (if enabled).
Secondary: “I already have an account”.
Skip to guest board view (limited).
Accessibility: VoiceOver reads each slide fully; large CTAs.

Screen 2: Phone OTP / Auth

Clean centered card.
Large phone input with country code prefill (+234).
“Send code” → 6-digit large digit inputs with auto-focus and paste support.
Resend timer + rate-limit friendly messaging.
Success → progressive verification prompt (Workplace ID → NIN hash later).

Screen 3: Home / Go Board (The Heart — Map + List Hybrid)
Layout (mobile portrait priority):

Top 55–60% of screen: interactive map (Leaflet/OSM or OSRM) showing user location, nearby active trips as dots/vehicles, major junctions as demand heat (sized circles).
Bottom 40–45%: sliding bottom sheet (default half-height, expandable to full).
Horizontal Corridor Chips (Kubwa→CBD, Nyanya→Idu, Lugbe→CBD, etc.) with live counts (“12 leaving”, pulse on high demand).
Window presets: Now | Later | Tomorrow | Any (chips).
Live Trip Cards stacked vertically (or horizontal carousel on wider).
Each card: driver avatar + L-badge, route title, departure time + “Leaving soon” badge if ≤15 min, seats remaining (live via Reverb), fare or “Free”, score reasons chips (proximity, rating, etc.), IRI color indicator, primary “Book” or “Soft Hold” button.

Empty state: demand hotspots list + “Be the driver” CTA with pre-selected corridor.
Pull-to-refresh + live seat updates (Reverb trips channel).
Search / “Where to?” large floating input that expands into destination picker + OD suggestions from history + demand.

Interactions:

Tap chip → filter board + map.
Long-press card → preview sheet.
Soft-hold (feature-gated): 3-min countdown visible on card and in My Rides.
Map tap on vehicle → focus card.

Data: TripMatchingService scored results, DemandService::hotspots(), live seats, board_window presets.
Screen 4: Trip Detail / Booking Flow

Full-screen or large bottom sheet.
Map with route polyline + waypoints.
Driver card (avatar, score, verification, vehicle).
Seats selector (visual seats left).
Fare breakdown (fixed, subsidy priority indicator).
Payment method selector (Wallet dual-balance visual, cash, subsidy, ride-credit if eligible).
Soft-hold vs Instant Book toggle.
Confirm → success haptic + status timeline starts.
Accessibility: all prices and times announced clearly.

Screen 5: Live Journey / Tracking

Full-bleed map with live driver location (15s updates).
Bottom persistent card: ETA, “Driver 500m away”, call/chat buttons, progress steps (Booked → Arriving → Boarded → Completed).
Arrival notification + haptic.
Boarded → capture payment + impact calculation starts.
SOS / Share trip button always visible.

Screen 6: My Rides

Segmented: Upcoming | Past | Soft Holds.
Cards with status timeline (Change Control style).
Soft-hold cards show countdown + Confirm / Release.
Completed cards show impact (CO₂, trees) + rate driver.

Screen 7: Wallet

Dual balance hero: Cash | Subsidy Credits (visual priority: subsidy first).
Quick actions: Top-up, Withdraw, Transfer (P2P), View transactions.
Transaction list with idempotent references visible for trust.
Subsidy explanation tooltip / sheet (“MDA palliative — trackable”).

Screen 8: Impact & Green

Personal dashboard: total CO₂, trees equivalent, fuel saved, Green Points, level.
Certificates downloadable / shareable.
Leaderboard (workplace).
“How it works” educational cards.

Screen 9: Profile & Verification

Avatar + verification level progress (L0 → L3) with clear next step.
Saved trip templates (one-tap republish).
Settings: language (English/Pidgin preference), notifications, accessibility overrides, dark mode.
Logout / data export (NDPR).

Screen 10: Publish / Be the Driver (Driver flow)

Simple form: corridor select (chips), seats, departure time (smart defaults), free-volunteer toggle (gold), waypoints.
Preview card.
Templates: “Save this commute” + one-tap publish week.
Demand prompt banner if active (“12 people waiting at Berger for Kubwa→CBD”).

Supporting Screens

Demand check-in (“I’m at Berger, need ride to Secretariat, 2 pax”).
Road map / heatmap (Green/Yellow/Red IRI) — public or logged-in.
Admin/Ops Control Tower (desktop-leaning but responsive): Demand Calendar, Duty Roster, Road Heatmap, Subsidy reports, GTFS status. Keep consistent tokens but denser tables.

5. Success Metrics & Award Readiness Checklist

Time-to-book (cold start) ≤ 3 taps / <15 seconds for returning users.
Seat visibility & live updates feel instantaneous.
Accessibility: 100% of primary flows VoiceOver-passable; contrast ≥ 4.5:1.
Social Impact storytelling visible on every completed ride and home.
Delight: soft-hold countdown, leaving-soon pulse, impact trees, free-ride gold treatment.
Differentiation vs Uber/Google Maps: corridor chips + fixed price + subsidy + verification badges + road intelligence + demand “be the driver” loop.

This plan turns WorkRide into the definitive mobile-first, community-powered, socially impactful mobility experience for Nigeria and the Global South — clearer than Uber, more purposeful than Google Maps, and deeply human in the Apple tradition while remaining ruthlessly practical in the Elon tradition.
Start with Phase 0 (Design System). Every subsequent screen must consume only the tokens and components defined there. Do not invent new colors or spacing. When in doubt, reduce, clarify, and make the primary action larger.Execute with obsessive attention to the mobile thumb and the person standing at a dusty junction at 6:15 a.m. That is the user who will make WorkRide an award winner.
